# Подключение моделей

DAGENT работает с любой моделью двумя способами:

1. **API** - любой OpenAI-совместимый сервис или локальный сервер (LM Studio, Ollama, llama.cpp, vLLM), а также Anthropic.
2. **GGUF** - файл `.gguf` прямо в процессе DAGENT через `llama-cpp-python` (CPU, CUDA или Metal).

Моделей можно подключить сколько угодно и переключаться между ними на лету: `Ctrl+M`, кнопка модели в верхней панели или палитра команд. Для каждой задачи можно указать свою модель - `POST /api/chat` принимает `model_id`.

---

## 1. Быстрый старт: три клика

1. Запустите DAGENT (`python run.py` или `scripts/start.sh`).
2. Нажмите **«Подключить модель»** - откроется мастер.
3. Выберите провайдера из списка, вставьте API-ключ и нажмите **«Проверить»**. DAGENT запросит список моделей у провайдера, подставит его в выпадающий список и скажет, всё ли работает.

Готово: выбирайте режим и пишите задачу.

## 2. Готовые пресеты провайдеров

Пресет - это просто заполненный `base_url` и подходящие значения по умолчанию. В мастере 18 штук:

| Пресет | `base_url` | Комментарий |
| --- | --- | --- |
| `openai` | `https://api.openai.com/v1` | GPT-4o, GPT-4.1, o-серия |
| `anthropic_proxy` | `https://api.anthropic.com/v1` | Через OpenAI-совместимый прокси; нативный API - ниже |
| `openrouter` | `https://openrouter.ai/api/v1` | Один ключ на сотни моделей |
| `deepseek` | `https://api.deepseek.com/v1` | Дёшево и хорошо кодит |
| `groq` | `https://api.groq.com/openai/v1` | Очень быстрый инференс |
| `mistral` | `https://api.mistral.ai/v1` | Mistral / Codestral |
| `together` | `https://api.together.xyz/v1` | Открытые модели |

| `xai` | `https://api.x.ai/v1` | Grok |

| `qwen` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | Qwen |
| `siliconflow` | `https://api.siliconflow.cn/v1` | Qwen, DeepSeek, Llama |

Список пресетов доступен и из API: `GET /api/models/presets`.

## 3. Локальные модели через сервер (рекомендуется)

Если у вас нет компилятора или не хочется собирать `llama-cpp-python`, запустите модель отдельной программой и подключите её как обычный API. Это самый надёжный путь, и он работает без сборки.

### LM Studio

1. Скачайте модель в LM Studio.
2. Вкладка **Developer** -> **Start Server** (порт по умолчанию `1234`).
3. В DAGENT: пресет **LM Studio**, API-ключ - любой текст (например `lm-studio`), модель - из списка.

### Ollama

```bash
ollama pull qwen2.5-coder:7b
ollama serve          # обычно уже запущен как служба
```

В DAGENT: пресет **Ollama**, ключ - любой (например `ollama`), модель - `qwen2.5-coder:7b`.

### llama.cpp server

```bash
llama-server -m ~/models/qwen2.5-coder-7b-instruct-q4_k_m.gguf --port 8080 -c 16384
```

В DAGENT: пресет **llama.cpp server**, модель - любая строка (сервер отдаёт загруженную модель).

### vLLM / KoboldCpp

То же самое: пресет, `base_url`, ключ при необходимости.

> «Проверить соединение» запросит `/models` у сервера и покажет, что реально доступно.

## 4. GGUF внутри DAGENT

Здесь модель грузится прямо в процесс DAGENT - отдельный сервер не нужен.

### Установка llama-cpp-python

```bash
# CPU
pip install llama-cpp-python

# NVIDIA CUDA
CMAKE_ARGS='-DGGML_CUDA=on' pip install llama-cpp-python --upgrade --force-reinstall

# Apple Silicon (Metal)
CMAKE_ARGS='-DGGML_METAL=on' pip install llama-cpp-python --upgrade --force-reinstall
```

Нужен компилятор C++ (`build-essential` + `cmake` в Linux, Xcode Command Line Tools в macOS, Visual Studio Build Tools в Windows). DAGENT проверяет доступность при старте: вкладка **Настройки -> Модели -> Локальные GGUF** показывает статус и эту же подсказку, если пакета нет (`GET /api/models/gguf/status`).

### Подключение файла

1. Скачайте `.gguf` (например Q4_K_M или Q5_K_M - хороший баланс).
2. Настройки -> Модели -> **Локальные GGUF** -> «Найти файлы»: DAGENT просканирует `gguf.scan_dirs` (по умолчанию `~/Downloads`, `~/models`, `~`) и покажет найденное с размерами.
3. Выберите файл - профиль создастся автоматически.
4. При желании нажмите «Предзагрузить», чтобы модель легла в память заранее и первый ответ не тормозил.

### Параметры llama.cpp

Глобальные значения в `gguf.*` (см. [docs/SETTINGS.md](SETTINGS.md)), а для конкретного профиля - в `gguf_options` (они перекрывают глобальные):

| Параметр | Что делает | Разумное значение |
| --- | --- | --- |
| `n_ctx` | Размер контекста | 4096-32768 (больше = больше памяти) |
| `n_gpu_layers` | Слоёв на GPU, `-1` = все | `-1` при CUDA/Metal, иначе `0` |
| `n_threads` | Потоков CPU | число физических ядер |
| `n_batch` | Размер батча | 512 |
| `chat_format` | Шаблон чата | `auto`, либо `chatml`, `llama-3`, `mistral-instruct` |
| `use_mmap` | Загрузка через mmap | `true` |
| `use_mlock` | Держать в RAM | `false` (включайте, если память вытесняется) |
| `main_gpu` | Индекс GPU | `0` |
| `verbose` | Лог llama.cpp | `false` |

В кэше держится до двух моделей одновременно, поэтому переключение между двумя локальными профилями быстрое. «Выгрузить» освобождает память (`POST /api/models/gguf/unload`).

## 5. Anthropic (нативный API)

При создании модели выберите тип **Anthropic**:

* `base_url`: `https://api.anthropic.com` (по умолчанию)
* `api_key`: ключ `sk-ant-...`
* `model`: `claude-sonnet-4-5` или другой доступный вам

DAGENT сам добавит заголовки `x-api-key`, `anthropic-version` и преобразует историю вызовов инструментов в формат Anthropic.

## 6. Возможности модели (capabilities)

В карточке модели есть переключатели, которые меняют поведение DAGENT:

| Флаг | Зачем |
| --- | --- |
| `native_tools` | Модель поддерживает function calling. Если выключить - DAGENT передаст инструменты текстом и сам разберёт JSON-ответ (работает даже с маленькими локальными моделями). |
| `vision` | Модель принимает картинки - можно прикреплять изображения к сообщению. |
| `context_window` | Размер окна в токенах. По нему считается шкала заполненности контекста и решается, когда сжимать историю. |
| `emulate_tool_role` | Для серверов, которые не принимают роль `tool`: результаты инструментов отправляются как `user`. |

Дополнительно в профиле есть `extra_headers` (свои HTTP-заголовки) и `extra_body` (поля в тело запроса - например `reasoning_effort` или `top_k` конкретного провайдера).

## 7. Параметры генерации

У каждой модели - свой набор `params`: `temperature`, `top_p`, `top_k`, `max_tokens`, `frequency_penalty`, `presence_penalty`, `repeat_penalty`, `stop_sequences`, `seed`. Приоритет такой:

1. значения профиля модели,
2. затем глобальные `agent.*` из настроек,
3. затем значения выбранного режима.

То есть режим задаёт разумную базу, а в настройках можно докрутить под себя.

## 8. Управление профилями

| Действие | Где | API |
| --- | --- | --- |
| Добавить | Модели -> «Подключить модель» | `POST /api/models` |
| Изменить | Карточка модели -> «Изменить» | `PUT /api/models/{id}` |
| Дублировать | Карточка модели | `POST /api/models/{id}/duplicate` |
| Сделать активной | Клик по модели / `Ctrl+M` | `POST /api/models/{id}/activate` |
| Проверить | «Проверить соединение» | `POST /api/models/{id}/test` |
| Список моделей у провайдера | «Получить список» | `GET /api/models/{id}/remote` |
| Удалить | Карточка модели | `DELETE /api/models/{id}` |
| Проверить несохранённый профиль | Мастер добавления | `POST /api/models/probe` |

Профили хранятся в `~/.dagent/settings.json`; API-ключи в ответах сервера маскируются (настройка `models.hide_keys`), а в браузер ключ не отдаётся вовсе. Обновление профиля с пустым или маскированным ключом сохраняет старый ключ - его не приходится вводить заново.

## 9. Без интернета и без ключей: демо-режим

Хотите посмотреть, как это работает, не подключая ничего?

```bash
python scripts/demo.py
```

Скрипт поднимает встроенную демо-модель (`dagent/demo_model.py`, OpenAI-совместимый сервер на `127.0.0.1:8611`), создаёт и активирует профиль «Демо-модель (офлайн)», наполняет рабочую папку примерами файлов и запускает интерфейс. Демо-модель отвечает мгновенно и умеет вызывать инструменты: покажет дерево папки, создаст `DEMO.md`, прочитает файл, выполнит команду. Всё полностью локально, ни одного внешнего запроса.

```bash
python scripts/demo.py --port 8420 --workspace ~/DAGENTDemo --fresh --no-browser
```

Отдельно демо-модель запускается так:

```bash
python -m dagent.demo_model --demo --port 8611
```

## 10. Если что-то не работает

| Симптом | Причина и решение |
| --- | --- |
| «Connection refused» на `localhost` | Локальный сервер не запущен или слушает другой порт. Проверьте LM Studio/Ollama и порт в `base_url`. |
| 401 / 403 | Неверный или просроченный ключ; у OpenRouter проверьте также формат `model` (`провайдер/модель`). |
| 404 model not found | Имя модели не совпадает с тем, что отдаёт провайдер. Нажмите «Получить список моделей». |
| Инструменты не вызываются | Выключите `native_tools` в карточке модели - DAGENT перейдёт на текстовый протокол. |
| GGUF: «llama-cpp-python is not installed» | Установите пакет (раздел 4) или запустите модель через локальный сервер. |
| Медленный первый ответ на GGUF | Предзагрузите модель или уменьшите `n_ctx` / `n_gpu_layers`. |
| Обрывается длинный ответ | Увеличьте `agent.request_timeout` и `max_tokens`. |
