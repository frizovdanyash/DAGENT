# Безопасность

DAGENT - это агент, который **реально выполняет команды и меняет файлы**. Поэтому безопасность здесь не «галочка в настройках», а несколько независимых слоёв. Каждый слой работает сам по себе: даже если вы включили автопилот, запрещённые команды останутся запрещёнными, а защищённые пути - недоступными.

---

## Слои защиты

| # | Слой | Что делает |
| --- | --- | --- |
| 1 | **Песочница рабочей папки** | Все пути разрешаются относительно `workspace.root`; выход наружу блокируется, включая символьные ссылки |
| 2 | **Защищённые пути** | `security.sensitive_paths` - системные папки и ключи недоступны ни при каких настройках |
| 3 | **Чёрный список команд** | `security.denied_commands` - регулярные выражения, команда блокируется до выполнения |
| 4 | **Классификация риска** | Каждое действие получает риск `low` / `medium` / `high` / `blocked` и объяснение |
| 5 | **Подтверждения** | Рисковые действия ждут вашего решения в интерфейсе; есть таймаут авто-отказа |
| 6 | **Отдельные выключатели** | Можно полностью запретить удаление, `web_fetch`, `python_run`, запись вне папки |
| 7 | **Журнал действий** | Каждое подтверждение и отказ пишется в БД и в `logs/audit.log` |
| 8 | **Защита локального API** | Токен, проверка `Origin`, привязка к `127.0.0.1` по умолчанию |

---

## 1. Песочница

```
workspace.root              = ~/DAGENTWorkspace
workspace.sandbox           = true          # держать агента внутри папки
workspace.allow_read_outside = false        # чтение вне папки запрещено
security.allow_write_outside_workspace = false
```

Как это работает: любой путь из аргументов инструмента (`path`, `source`, `destination`) раскрывается (`~`), превращается в абсолютный и, если цель существует, разрешается через `Path.resolve()` - так ловятся символьные ссылки, ведущие наружу. Затем проверяется, что путь лежит внутри рабочей папки, и что он не совпадает с защищённым.

Если очень нужно работать с другой папкой - просто **смените рабочую папку** (кнопка папки в верхней панели), а не открывайте весь диск. Это безопаснее и понятнее: дерево, поиск и «изменённые файлы» будут относиться к ней.

---

## 2. Защищённые пути

По умолчанию закрыты:

```
/etc  /root  /proc  /sys  /boot  /dev
~/.ssh  ~/.aws  ~/.gnupg
C:\Windows  C:\Program Files
```

Список можно дополнить в **Настройки -> Безопасность -> Защищённые пути** (по одному пути на строку). Совпадение проверяется по самому пути и по всему, что внутри него.

## 3. Запрещённые команды

Регулярные выражения из `security.denied_commands` (регистр не важен). Команда, попавшая под любое из них, **не выполняется вообще** - агент получает отказ с объяснением, а в журнале появляется запись `blocked`.

Стандартный список закрывает:

* `rm -rf /` и варианты (кроме `/home` и `/tmp`), форк-бомба `:(){ :|:& };:`
* `mkfs...`, `dd if=... of=/dev/...`, запись в `/dev/sd*`
* `shutdown`, `reboot`, `halt`, `poweroff`
* `chmod -R 777 /`
* `format C:`, `rd /s /q C:\`, `Remove-Item -Recurse C:\`
* `curl ... | sh` и `wget ... | sh` (запуск скрипта из интернета)
* `git push --force ... main`

Плюс список ключевых слов повышенного риска (`HIGH_RISK_KEYWORDS`): `sudo`, `su`, `chmod -r`, `chown -r`, `git reset --hard`, `git clean -fd`, `curl`, `wget`, `nc`, `ssh`, `scp`, `rsync`, `pip install`, `npm install -g`, `apt install`, `brew install`, `docker rm`, `docker system prune`, `kubectl delete`, `truncate`, `shred`, `powershell -enc`, `iex`, `invoke-expression`, `set-executionpolicy`, `remove-item -recurse`, `reg add/delete`, `del /f`, `rmdir /s`, `npm publish`, `kill -9 1` и т. п. Такие команды **не блокируются**, но помечаются как `high` и требуют подтверждения.

## 4. Оценка риска

Каждый вызов инструмента проходит через `SafetyEngine.decide()` и получает одну из меток:

| Риск | Примеры | Что происходит |
| --- | --- | --- |
| `low` | `read_file`, `list_dir`, `workspace_tree`, `search_files`, `ls`, `git status`, `echo` | Выполняется сразу |
| `medium` | `write_file`, `edit_file`, `move_path`, `run_command` с пайпами/перенаправлениями, `web_fetch`, `python_run` | Подтверждение, если не включён авто-режим |
| `high` | `delete_path`, команды с `sudo`, `rm -r`, `curl`, установщики пакетов, `python_run` с `subprocess`/`socket`/`shutil.rmtree` | Подтверждение с явным предупреждением |
| `blocked` | Совпадение с чёрным списком, выход за песочницу, отключённый инструмент | Не выполняется, агент получает причину |

Цвет метки виден в карточке инструмента в чате - сразу понятно, что происходит.

## 5. Подтверждения

Когда действие требует решения, выполнение **приостанавливается**, и в чате появляется карточка:

* что за инструмент и какие аргументы,
* риск и причина,
* **превью**: diff для правки файла, содержимое для записи, полная команда для выполнения,
* кнопки: «Разрешить», «Запретить» и выбор области разрешения.

Области («запомнить»):

| Область | Ключ запоминания | Действует |
| --- | --- | --- |
| `once` | - | Только этот вызов |
| `session_tool` | `tool:<имя>` | Этот инструмент до конца сессии |
| `session_command` | `cmd:<сигнатура>` | Эта команда до конца сессии |
| `session_folder` | `write:<папка>` | Запись в эту папку до конца сессии |
| `always` | как выше, но надолго | До перезапуска |

Память разрешений живёт в рамках сессии и сбрасывается при её смене - это осознанное решение: «разрешить всё навсегда» в DAGENT нет.

Если вы не ответили, через `security.confirm_timeout` (по умолчанию 300 секунд) действие автоматически **отклоняется**, и агент продолжает работу, зная об отказе. Ничего не зависает.

Аналогично работает `ask_user`: модель задаёт вопрос, выполнение ждёт ответа.

---

## 6. Режимы и подтверждения

| Режим | Подтверждения | Комментарий |
| --- | --- | --- |
| `chat` | - | Инструментов нет вовсе |
| `assistant` | на каждое действие | Безопасный режим по умолчанию |
| `code` / `terminal` | на каждое действие | Много инструментов, но под контролем |
| `analyst` | не нужны | Только чтение: менять файлы и запускать команды не может |
| `autopilot` | не нужны | Все инструменты кроме `ask_user`; используйте в папке, которую не жалко, и под git |

Глобальный переключатель `security.auto_approve` включает автопилот для всех режимов. Отдельно `security.auto_approve_reads = true` пропускает без подтверждения только чтение и простые безопасные команды - это удобный баланс на каждый день.

---

## 7. Отдельные выключатели

| Настройка | Отключает |
| --- | --- |
| `security.allow_delete` | `delete_path` |
| `security.confirm_delete` | Подтверждение при удалении |
| `security.allow_network_tools` | `web_fetch` |
| `security.allow_python_exec` | `python_run` |
| `security.allow_write_outside_workspace` | Запись вне рабочей папки |
| `workspace.allow_read_outside` | Чтение содержимого файлов вне рабочей папки |

Отключённый инструмент просто убирается из набора, который видит модель, - она не будет пытаться его вызвать, а если попытается, получит понятный отказ.

## 8. Ограничения выполнения

| Настройка | По умолчанию | Зачем |
| --- | --- | --- |
| `security.command_timeout` | 120 с | Команда не может висеть вечно |
| `security.max_output_chars` | 120 000 | Огромный вывод обрезается (и не съедает контекст) |
| `security.max_file_write_bytes` | 8 МБ | Защита от записи гигантских файлов |
| `security.max_file_read_bytes` | 2 МБ | Чтение больших файлов по частям |
| `agent.max_iterations` | по режиму | Ограничение длины агентного цикла |
| `security.shell` | `auto` | `bash`/`sh` в Linux и macOS, PowerShell или `cmd` в Windows, либо своя оболочка |

## 9. Журнал действий

При `security.audit_log = true` пишутся:

* каждое действие, потребовавшее подтверждения, с решением и областью;
* отказы и блокировки с причиной;
* команды встроенного терминала.

Смотреть: **Мониторинг -> Журнал** или `GET /api/audit?limit=200`. Файл: `~/.dagent/logs/audit.log`, база: `~/.dagent/data/sessions.db`.

Записи появляются только тогда, когда было что подтверждать или отклонять: в полностью автоматическом режиме журнал может быть пустым - это нормально.

## 10. Защита локального API

DAGENT поднимает веб-сервер, и важно, чтобы им не управлял кто-то ещё:

* **Привязка к localhost.** По умолчанию `app.host = 127.0.0.1` - из интернета сервер недоступен. Меняйте на `0.0.0.0`, только если сознательно открываете доступ из локальной сети.
* **Токен.** При первом запуске генерируется `app.token_secret`. Он вставляется в страницу (`window.DAGENT_BOOT.token`) и отправляется в заголовке `X-DAGENT-Token`, а для WebSocket - в `?token=`. Запросы без верного токена получают `403`. Исключения - `/api/health` и `/api/ping`. Через API токен изменить нельзя (`token_secret` отфильтровывается при сохранении настроек).
* **Проверка Origin.** Запросы с чужим `Origin` отклоняются - защита от drive-by атак, когда вредоносная страница в браузере дёргает ваш локальный сервер. Разрешённые адреса: `localhost`/`127.0.0.1` на вашем порту и список `app.allowed_origins` (нужен для туннелей и обратных прокси; редактируется в **Настройки -> Безопасность**).
* **Ключи моделей не уезжают в браузер.** `models.hide_keys` маскирует API-ключи в ответах сервера, а в настройках ключ показывается только при явном нажатии «показать».
* **Режим разработчика.** `app.dev_mode = true` отключает токен, открывает CORS и Swagger на `/api/docs`. Включайте только на время отладки и на своей машине.

## 11. Практические рекомендации

1. **Держите проект под git.** Тогда любую правку агента можно откатить: `git status`, `git diff`, `git checkout .`. В интерфейсе есть вкладка «Файлы» со списком изменённых файлов за сессию.
2. **Начинайте с `assistant`.** Посмотрите, как модель работает, и только потом включайте автопилот.
3. **Давайте агенту отдельную папку.** Не указывайте в `workspace.root` домашний каталог или корень диска.
4. **Проверяйте превью перед подтверждением.** Для правок показывается diff, для записи - содержимое, для команд - полный текст.
5. **Осторожно с `autopilot` + `security.auto_approve`.** Это максимальная скорость и минимальный контроль. Хорошее сочетание: отдельная папка, git, `deny`-список по умолчанию и ограничение `agent.max_iterations`.
6. **Не храните секреты в рабочей папке.** Всё, что там лежит, модель может прочитать и отправить провайдеру как часть контекста.
7. **API-ключи** лежат в `~/.dagent/settings.json` в открытом виде (как у большинства локальных инструментов). Ограничьте права на файл и не публикуйте его.

## 12. Что DAGENT не делает

* Не отправляет данные куда-либо, кроме выбранной вами модели (и `web_fetch`, если вы его включили).
* Не имеет телеметрии, аналитики и внешних зависимостей в интерфейсе - все CSS/JS лежат в репозитории, CDN не используется.
* Не выполняет команды от имени другого пользователя и не повышает привилегии (`sudo` помечается как высокий риск и требует подтверждения).
* Не хранит историю в облаке: сессии, настройки и журнал - локальные файлы в `~/.dagent`.
