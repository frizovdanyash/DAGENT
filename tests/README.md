# Тесты DAGENT

Три независимых набора. Все работают **офлайн**: ни один тест не обращается к внешним API и не требует ключей моделей - вместо настоящей модели используется встроенная демо-модель `dagent/demo_model.py` (OpenAI-совместимый сервер, отвечающий заранее заданным сценарием).

Запускаются из корня репозитория:

```bash
python tests/test_agent_flow.py                 # 118 проверок бэкенда
python tests/test_websocket.py                  # 28 проверок живого сервера и WebSocket
npm install && node tests/test_frontend.mjs     # 87 проверок интерфейса
```

Каждая проверка печатается по ходу (`ok <имя>` или `FAIL <имя> <причина>`), в конце - итог:

```
PASSED 118   FAILED 0
```

Код возврата `0` означает, что падений нет; при падении печатается список провалившихся проверок.

## 1. `test_agent_flow.py` - бэкенд, 118 проверок

**Что нужно:** Python 3.10+, установленные зависимости (`pip install -r requirements.txt`). Node.js не нужен.

```bash
python tests/test_agent_flow.py
```

Проверки сгруппированы по секциям (`== boot ==`, `== models ==`, `== sessions ==`, `== agent run: tools + files (autopilot) ==`, `== safety: approvals (assistant mode) ==`, `== safety: blocked commands ==`, `== workspace & filesystem ==`, `== terminal ==`, `== audit & search ==`, `== settings ==`, `== export / duplicate / summarize / clear ==`, `== stop a running task ==`, `== security: token & origin ==`, `== store ==`), в конце - итог и время прогона.

**Как устроен.** Приложение поднимается in-process через `httpx.ASGITransport` - настоящий HTTP-сервер не запускается, порты не занимаются. Lifespan входит вручную:

```python
async with app.router.lifespan_context(app):
    ...
```

Демо-модель стартует на свободном порту в отдельном потоке, профиль модели создаётся во временном `DAGENT_HOME`, поэтому ваши реальные настройки и сессии не затрагиваются.

**Что проверяет** (секции и проверки - ровно те, что печатаются при прогоне):

| Секция | Что внутри |
| --- | --- |
| `boot` | демо-модель поднялась, папка данных создана |
| `health & bootstrap` | `GET /api/health`, `GET /` отдаёт интерфейс, токен внедрён в `window.DAGENT_BOOT`, в HTML не осталось шаблонов, раздаются все CSS/JS-модули |
| `GET /api/state` | наличие `settings`, `defaults`, `modes`, `tools`, `providers`, `workspace`, `system`, `models`, `sessions`; 6 режимов, 17 инструментов, применённая рабочая папка, горячие клавиши |
| `models` | пресеты, создание профиля, маска API-ключа в ответе, список моделей у провайдера, `probe`, `test`, `activate`, `duplicate`, удаление, GGUF-статус |
| `sessions` | создание сессии, список |
| `agent run: tools + files (autopilot)` | полный прогон задачи: `run.start`, `token`, `reasoning`, `tool.start`, `tool.result`, `plan`, `context`, `message.saved`, `run.end`, статус `done`, счётчики итераций/инструментов/токенов; `read_file`, `run_command` с выводом, `write_file` создал файл; сообщения сохранились, у ответов ассистента в `meta` лежат `tool_calls` и `tool_results` с правильными `call_id`, счётчик использования модели вырос |
| `safety: approvals (assistant mode)` | `approval.required` с инструментом и превью, выполнение действительно ждало ответа, после разрешения задача завершилась |
| `safety: blocked commands` | `rm -rf /` блокируется, команда с пайпом в shell не считается низкой по риску, `ls -la` безопасна |
| `workspace & filesystem` | выход за рабочую папку запрещён, запись наружу блокируется или требует разрешения, `list_dir` внутри папки разрешён, дерево рабочей папки, просмотр файловой системы, чтение файла, чтение вне папки запрещено по умолчанию, смена рабочей папки |
| `terminal` | выполнение команды через `/api/terminal` и блокировка опасной команды |
| `audit & search` | журнал действий и поиск по данным |
| `settings` | частичное обновление, полный документ, сохранение темы, токен не уходит в браузер, схема, экспорт, импорт, санитизация опасных полей |
| `export / duplicate / summarize / clear` | экспорт сессии в Markdown и JSON, дублирование, суммаризация (с реальным вызовом модели), очистка, удаление |
| `stop a running task` | остановка выполнения и статус `stopped` |
| `security: token & origin` | `/api/health` без токена, `403` без токена, `200` с токеном, чужой `Origin` отклоняется, свой `Origin` всё равно требует токен, верный токен работает и с чужим `Origin` |
| `store` | счётчики и поиск на уровне хранилища |

## 2. `test_websocket.py` - живой сервер, 28 проверок

**Что нужно:** то же, что и для первого набора.

```bash
python tests/test_websocket.py
```

**Зачем отдельный набор.** `httpx.ASGITransport` не умеет WebSocket, а `/ws` - главный канал событий в интерфейсе. Этот тест запускает **настоящий `uvicorn`** отдельным процессом и подключается к настоящему сокету.

**Как устроен.** Тест пишет временный лаунчер `scripts/_ws_test_server.py` (он в `.gitignore`), поднимает сервер на свободном порту с временным `DAGENT_HOME`, дожидается готовности по `/api/health` и проходит полный цикл задачи. После окончания процесс останавливается, временные файлы удаляются.

**Что проверяет** (28 проверок):

* поднялась демо-модель и настоящий `uvicorn`, `GET /` отдаёт интерфейс, CSS и JS раздаются, favicon на месте, SPA catch-all возвращает оболочку;
* `/api/health` доступен без токена, `/api/state` показывает демо-модель (тест работает в `dev_mode`, поэтому токена нет);
* рукопожатие WebSocket: кадр `hello` с версией и системной информацией, `ping`/`pong`;
* задача: `POST /api/chat` принят, по сокету приходят `run.start`, поток токенов, события инструментов, `approval.required`, затем `run.end` и успешный статус;
* подтверждение разрешается **через сокет** (`{"kind": "resolve", ...}`), выполнение продолжается;
* выполнение принадлежит сессии, сообщения и ответ ассистента сохранены, название сессии придумано автоматически;
* после подтверждений запись появилась в журнале;
* остановка через `{"kind": "stop"}` принимается, активных выполнений не остаётся.

**Важно про подтверждения.** Чтобы тест действительно получил `approval.required`, в нём выставлено `security.auto_approve_reads = false`, а запрос к демо-модели сформулирован так, чтобы она вызвала `run_command` (в тексте есть ключевое слово команды, но нет слов «структура», «проект», «создай», «прочитай» - они уводят демо-модель на другие инструменты). Чтение файлов подтверждения не требует никогда, а `echo` входит в `security.always_allow_commands`.

Записи в `/api/audit` появляются **только** когда было подтверждение или отказ - пустой журнал в обычном прогоне это норма.

## 3. `test_frontend.mjs` - интерфейс, 87 проверок

**Что нужно:** Node.js 18+ и `jsdom`:

```bash
npm install          # ставит только jsdom, больше ничего
node tests/test_frontend.mjs
DAGENT_DEBUG=1 node tests/test_frontend.mjs    # подробная диагностика падений
```

`package.json` в корне - только для разработки, в рантайме DAGENT Node.js не нужен.

**Как устроен.** jsdom поднимает настоящий `dagent/web/index.html`, затем тест загружает **реальные ES-модули** из `dagent/web/js/` - никакого мокирования логики интерфейса. Внешние вызовы подменяются:

* `fetch` отвечает записанными фикстурами из `tests/fixtures/`;
* `WebSocket` - управляемый заглушкой канал, в который тест сам отправляет события;
* `scrollIntoView`, `scrollTo`, `matchMedia`, `URL.createObjectURL` - заглушки (в jsdom их нет);
* `fetch`, `WebSocket`, `navigator` копируются на `globalThis` через `Object.defineProperty`, потому что модули используют их как глобальные.

**Что проверяет** (87 проверок, сгруппированы по шагам сценария):

| Блок | Проверки |
| --- | --- |
| Загрузка | интерфейс отрисовался по `window.DAGENT_BOOT`, запрошен `/api/state`, подключён WebSocket, 6 режимов в виде пилюль, список сессий, рабочая папка, имя и подпись модели, заголовок сессии, статус «онлайн», вкладки мониторинга, информационная сетка, дерево рабочей папки |
| Первый экран | 6 карточек быстрого старта, чек-лист настройки, карточки переведены и подставляют текст в поле ввода |
| Подтверждения | карточка показывает команду и превью, разрешение уходит через API |
| Рендер чата | все сохранённые сообщения, сообщение пользователя, ответы ассистента, карточки инструментов, пузырёк стриминга убирается после `run.end`, Markdown (списки и заголовки), блок кода с подсветкой, diff для `edit_file`, команда в карточке инструмента |
| Мониторинг | лента активности, план и счётчик прогресса, отслеживание изменённых файлов, шкала контекста, тост о завершении, кнопка отправки вернулась в обычный режим |
| Палитра | открывается по `Ctrl+K`, список действий, фильтрация по запросу, закрытие по `Escape` |
| Настройки | открываются по `Ctrl+,`, 8 разделов в навигации, каждый раздел что-то рисует, карточки моделей, карточки тем, палитра акцентов, смена темы применяется, строки горячих клавиш, раздел «О программе» указывает автора и ссылку на Telegram, закрытие диалога |
| Язык | переключение на английский и обратно на русский |
| Поле ввода | статистика символов, метка режима, `Enter` отправляет, в запросе есть текст и сессия, ввод очищается, кнопка переходит в режим «Стоп», появляется пузырёк стриминга, после `run.end` интерфейс возвращается в покой, слэш-меню показывает команды |
| Сессии | контекстное меню сессии, кнопка «Новая сессия» создаёт сессию |
| Вкладки мониторинга | `activity`, `plan`, `files`, `terminal`, `info` активируются; команда во встроенном терминале выполняется и вывод рисуется |
| Модели | переключатель показывает профили, клик активирует модель |
| Превью файла | строка файла доступна, изменённый файл открывает диалог превью, содержимое запрашивается через `/api/fs/file`, диалог закрывается |
| Мастер первого запуска | открывается, шаг 1 показывает языки, шаг 2 предлагает способы подключения модели, мастер можно пропустить и закрыть |
| Чистота | ни одной неперехваченной ошибки консоли, ни одной ошибки `window`, **все** обращения к сети прошли через заглушку (то есть тест не пытался уйти в интернет) |

**Особенности jsdom, о которых стоит помнить при правке теста:**

* закрытие диалога анимируется (~150 мс) - утверждения нужно оборачивать в `waitFor`;
* если в `state.run` осталось выполнение, `openSession()` добавляет подтверждение «Агент работает» первым диалогом - берите нужный через `.pop()` или закрывайте `closeTop()`;
* `state.changedFiles` очищается на `session:loaded`, поэтому проверка превью файла делает запасной путь через `#fileTree .tree-row`;
* названия режимов локализуются на сервере, поэтому после `language:changed` интерфейс заново запрашивает `/api/modes` - заглушка должна отдавать переведённые названия;
* предупреждение canvas «Not implemented» от jsdom безвредно.

## Фикстуры

`tests/fixtures/` - это **настоящие ответы API**, снятые с бэкенда (около 120 КБ, лежат в репозитории, чтобы интерфейсные тесты запускались без установки Python-зависимостей на CI).

Перезаписать:

```bash
python tests/capture_fixtures.py
```

Скрипт поднимает демо-модель на порту `8601` (переменная `DAGENT_MOCK_PORT`), прогоняет задачу и сохраняет:

```
state.json settings.json modes.json models.json sessions.json session.json
events.json runs.json workspace.json tree.json browse.json file.json
terminal.json audit.json export.md.txt
```

**Обязательно перезаписывайте фикстуры, если меняли формат ответов API или состав событий** - иначе jsdom-тесты будут проверять устаревший контракт и «зеленеть» невпопад.

## Демо-модель

`dagent/demo_model.py` - маленький OpenAI-совместимый сервер без единой внешней зависимости. Он нужен тестам, демо-режиму и разработке интерфейса.

```bash
python -m dagent.demo_model --demo --port 8611   # автономно
python scripts/demo.py                           # демо-модель + интерфейс + примеры файлов
```

Поведение зависит от текста запроса (так тесты выбирают нужный инструмент):

| В запросе есть | Что сделает |
| --- | --- |
| «структур», «проект», «tree» | `workspace_tree` |
| «создай», «write» | `write_file DEMO.md` |
| «прочитай», «read» | `list_dir` |
| иначе | `run_command echo ... && python3 -V` |

Сценарий ответов можно задать программно: `set_script([...])`, `set_demo(...)`, `demo_reply(...)` - этим пользуются оба бэкенд-теста.

## Что тесты не покрывают

* **Визуальная часть.** CSS, темы, плотности, адаптивность проверяются только глазами - запустите `python scripts/demo.py` и посмотрите 7 тем, 3 плотности, свёрнутые панели и узкую ширину окна.
* **Настоящие провайдеры.** Запросы к OpenAI/DeepSeek/Anthropic в тестах не выполняются; проверяются только контракт провайдера и обработка ошибок на демо-модели.
* **Реальный `llama-cpp-python`.** GGUF-провайдер тестируется на уровне статуса и подсказки об установке (пакет требует компиляции и в CI не ставится).
* **Windows и macOS.** Наборы прогонялись в Linux; платформенные ветки (оболочка, пути, `fs/open`) покрыты кодом, но не запуском.
